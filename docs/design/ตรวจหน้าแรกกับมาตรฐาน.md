# ตรวจหน้าแรกของรุ่น 2 กับมาตรฐาน

พี่เอมสั่ง 5 ก.ย. 2569 ว่า *"ผมเอาแบบศึกษาเป็นหน้าแรก ผมชอบแบบที่เป็นอยู่ แค่ต้องการให้ตรวจสอบกับมาตรฐาน ว่าผ่านไหม ต้องปรับตรงไหนบ้าง"*

ใบนี้จึงไม่ใช่การออกแบบใหม่ เป็นการเอาของที่เสิร์ฟผู้อ่านอยู่จริงวันนี้ไปวัดกับมาตรฐาน แล้วบอกว่าต้องปรับตรงไหน

## ผมเปิดอะไรดู และวัดอย่างไร

เปิด <https://phrakham.life> ด้วยเบราว์เซอร์จริง แล้ววัดเอง ไม่ได้อ่านจากบทความ

| วัดอะไร | ทำอย่างไร |
| - | - |
| เกณฑ์ที่เครื่องตรวจได้ | ยิง axe-core รุ่น 4.10.2 เลือกเฉพาะกฎ WCAG ระดับ A กับ AA |
| สีตัวหนังสือ | คำนวณอัตราส่วนความสว่างเองจากสีที่เบราว์เซอร์คำนวณแล้ว เทียบทั้งเกณฑ์ 4.5 ของ AA และเกณฑ์ 7 ที่บริษัทเรารับมาเอง |
| ขนาดปุ่ม | วัดกล่องจริงของทุกปุ่มและทุกลิงก์ที่กดได้ เทียบเกณฑ์ 44 คูณ 44 |
| ล้นขอบจอ | ย่อจอเหลือ 320 จุด แล้วเทียบความกว้างที่เลื่อนได้กับความกว้างจอ ทำ 3 สภาพ คือปกติ ใส่ระยะตัวอักษรตามเกณฑ์ 1.4.12 และขยายตัวอักษรเป็น 200% |
| กรอบตอนกดแป้น Tab | กดแป้น Tab จริงแล้วอ่านค่าที่เบราว์เซอร์คำนวณของตัวที่กำลังโฟกัส |
| ARIA | ไล่อ่าน role ทุกตัวบนหน้า และตรวจว่าตัวชี้ข้ามกันชี้ไปที่ไม่มีอยู่จริงหรือเปล่า |

รันซ้ำได้ ตัวเลขทุกตัวข้างล่างมาจากการวัดครั้งนี้ ไม่ได้คัดมาจากที่อื่น

## สรุปสั้น

ของที่เป็นอยู่แข็งแรงกว่าที่ผมคิดไว้ เครื่องตรวจผ่าน 30 กฎ และเจอของเสียแค่เรื่องเดียวคือสีจาง

แต่ของที่เครื่องตรวจไม่ได้ ยังมีที่ต้องแก้อีก 3 เรื่อง ซึ่งทั้ง 3 เรื่องเป็นเกณฑ์ระดับ AA ที่บังคับ ไม่ใช่ของเสริม

## ต้องแก้ เพราะมาตรฐานบังคับ

### 1 สีตัวหนังสือจางเกินเกณฑ์ 3 จุด

เกณฑ์ SC 1.4.3 ระดับ AA บอกว่าตัวหนังสือขนาดปกติต้องเข้มกว่าพื้นอย่างน้อย 4.5 เท่า

สีน้ำตาลอ่อนที่ใช้อยู่คือ `#8c7a4e` บนพื้นขาว วัดได้ **4.19 เท่า** ยังไม่ถึง ใช้อยู่ 3 จุด คือป้ายบทความล่าสุด วันที่แก้ไข และลิงก์ดูทั้งหมด

วิธีแก้คือทำสีนั้นให้เข้มขึ้นอีกนิดเดียว ไม่ต้องเปลี่ยนโทนสีของเว็บ

### 2 ขยายตัวอักษรเป็นสองเท่าแล้วหน้าล้นขอบ

เกณฑ์ SC 1.4.4 ระดับ AA บอกว่าผู้อ่านต้องขยายตัวอักษรเป็น 200% ได้โดยไม่เสียเนื้อหาและไม่ต้องเลื่อนจอซ้ายขวา

ที่จอ 320 จุด พอขยายตัวอักษรเป็น 200% ความกว้างที่เลื่อนได้กลายเป็น **417 จุด** คือ **ล้นออกไป 97 จุด**

ตัวที่ดันให้ล้นคือแถบเมนูบนสุด ปุ่มสามขีด ป้ายวันที่ และป้ายข้ออ้างอิงสีส้ม

เรื่องนี้สำคัญกับเว็บนี้เป็นพิเศษ เพราะคนที่ขยายตัวอักษรเป็นสองเท่าคือคนสายตาไม่ดี ซึ่งเป็นคนกลุ่มเดียวกับที่มาอ่านพระคัมภีร์บนมือถือ

### 3 ปุ่มสามขีดกับช่องพิมพ์อ้างอิง ไม่มีกรอบตอนกดแป้น Tab

เกณฑ์ SC 2.4.7 ระดับ AA บอกว่าตัวที่กำลังโฟกัสต้องมองเห็นได้

ผมกดแป้น Tab จริงแล้วอ่านค่าที่เบราว์เซอร์คำนวณ พบว่า 2 ตัวนี้ถูกสั่งปิดกรอบไว้ทั้งที่เบราว์เซอร์รู้ว่าควรโชว์

| ตัวที่ไม่มีกรอบ | ผลที่วัดได้ |
| - | - |
| ปุ่มสามขีดเปิดเมนู | กรอบถูกตั้งเป็น none และไม่มีเงาแทน |
| ช่องพิมพ์ข้ออ้างอิง | กรอบถูกตั้งเป็น none และไม่มีเงาแทน |

คนที่ใช้แป้นพิมพ์อย่างเดียวจะไม่รู้ว่าตัวเองอยู่ตรงไหน สองตัวนี้เป็นทางเข้าหลักของหน้าด้วย

### 4 ปุ่มเปิดเมนูใส่ป้าย ARIA ผิดที่

แบบส่วนประกอบของ W3C เรื่องปุ่มเปิดเมนู บอกว่าตัวปุ่มได้ `aria-haspopup` กับ `aria-expanded` ส่วน `role="menu"` เป็นของกล่องเมนู ไม่ใช่ของปุ่ม

ของที่เป็นอยู่เอา `role="menu"` ไปใส่ที่ตัวปุ่ม ทำให้โปรแกรมอ่านจอประกาศว่าปุ่มนี้คือเมนู ทั้งที่มันเป็นแค่ปุ่มที่เปิดเมนู

มีอีกจุดที่คล้ายกันคือลิงก์ตัวหนึ่งใส่ `role="link"` ซ้ำกับสิ่งที่มันเป็นอยู่แล้ว และใส่ `aria-expanded` ทั้งที่ลิงก์ไม่ได้เปิดปิดอะไร

## ควรแก้ เพราะเป็นเกณฑ์ที่บริษัทเรารับมาเอง

รายการมาตรฐานของกลางเขียนไว้ว่าเรารับเกณฑ์ระดับ AAA มา 5 ข้อ สำหรับงานที่ผู้อ่านอายุมาก อ่านกลางแดด หรือยืนถือมือถือ เว็บอ่านพระคัมภีร์ตรงกับกลุ่มนี้พอดี

### 5 ปุ่มเล็กกว่า 44 จุด อยู่ 9 ปุ่ม

| ปุ่ม | ขนาดที่วัดได้ |
| - | - |
| ปุ่มขนาดตัวอักษร | 33 คูณ 33 |
| ปุ่มตั้งค่าการแสดงผล | 33 คูณ 33 |
| ปุ่มดาวน์โหลด | 33 คูณ 33 |
| ปุ่มค้นหาบนแถบบน | 38 คูณ 31 |
| ป้ายข้ออ้างอิงสีส้ม | สูง 24 |
| ลิงก์อ่านบทความ | สูง 26 |
| ลิงก์เล่าประสบการณ์ ท้ายหน้า | สูง 16 |
| ลิงก์สัญญาอนุญาต ท้ายหน้า | สูง 14 |

สามปุ่มแรกอยู่บนแถบเครื่องมือที่ผู้อ่านต้องใช้บ่อย ควรแก้ก่อน ส่วนลิงก์ท้ายหน้าที่สูง 14 จุด เป็นตัวที่เล็กที่สุดบนหน้า

### 6 สีอีก 8 คู่ยังไม่ถึงเกณฑ์ 7 เท่าที่เรารับมาเอง

ที่จางที่สุดคือ 4.19 ที่เข้มที่สุดในกลุ่มนี้คือ 6.59 คำโปรยใต้หัวเรื่องวัดได้ 6.49 และป้ายท้ายหน้าวัดได้ 4.63

ถ้าแก้ข้อ 1 อยู่แล้ว ขยับให้ถึง 7 ไปเลยจะจบทีเดียว

### 7 ปุ่มรูปล้วนไม่มีคำกำกับ 5 ปุ่ม

รายการมาตรฐานของกลางเขียนไว้ว่า ปุ่มที่เป็นรูปล้วนอนุญาตเฉพาะเมื่อรูปนั้นเป็นของจริงในโลกที่ทำหน้าที่นั้น และรูปนั้นต้องอยู่ในบัญชีที่อนุญาต

ห้าปุ่มนี้คือ เลือกพระคัมภีร์ แสดงหรือซ่อนภาษาเดิม เลือกฉบับ การจัดวาง และตัวเลือกการแสดงผล ทั้งห้าเป็นความคิดที่ไม่มีของจริงในโลก คนที่ไม่คุ้นจะเดาไม่ออกว่ากดแล้วได้อะไร

ปุ่มพวกนี้มีคำอธิบายสำหรับโปรแกรมอ่านจอครบแล้ว ที่ขาดคือคำที่คนตาดีมองเห็น

เรื่องนี้แบบร่างหน้าหลักของรุ่น 3 แก้ไปแล้วหนึ่งปุ่ม คือเติมคำว่าเลือกเล่มลงบนปุ่มรูปหนังสือ

### 8 กรอบโฟกัสที่มีอยู่ เป็นของที่เบราว์เซอร์แถมมา

12 ตัวที่ผ่าน ใช้กรอบค่าเริ่มต้นของเบราว์เซอร์ ซึ่งหนา 1 จุดตามที่เบราว์เซอร์รายงาน

เกณฑ์ที่เรารับมาเองบอกว่ากรอบต้องหนาอย่างน้อย 2 จุด และเข้มกว่าตอนไม่โฟกัสอย่างน้อย 3 เท่า

แปลว่าตอนนี้ผ่านขั้นต่ำของ AA แต่ยังไม่ถึงเกณฑ์ที่เราตั้งเอง และหน้าตาจะเปลี่ยนไปตามเบราว์เซอร์ที่ผู้อ่านใช้ เพราะเราไม่ได้ออกแบบมันเอง

### 9 ทั้งหน้าไม่มีหัวเรื่องระดับบนสุด

บนหน้ามีหัวเรื่องอยู่อันเดียว เป็นระดับสอง ชื่อว่าเลือกพระคัมภีร์ ซึ่งอยู่ในหน้าต่างที่ยังไม่เปิด

คนที่ใช้โปรแกรมอ่านจอมักกระโดดด้วยหัวเรื่อง พอไม่มีหัวเรื่องระดับบนสุด เขาจะไม่มีจุดเริ่ม

## เรื่องที่ชนกับสิ่งที่เคาะไว้แล้ว ต้องให้พี่เอมตัดสิน

`docs/เคาะ/หน้าจอกับการอ่าน.md` เขียนว่าเว็บนี้ไม่มีช่องค้นหาเลยทั้งเว็บ

แต่ของที่เป็นอยู่ซึ่งพี่เอมบอกว่าชอบ **มีช่องพิมพ์อยู่ 2 ช่อง** และเป็นคนละอย่างกัน

| ช่อง | ทำอะไร | อยู่ตรงไหน |
| - | - | - |
| ช่องค้นทั้งเว็บ | พิมพ์คำแล้วค้นทุกหน้า เป็นของที่ตัวสร้างเว็บรุ่น 2 แถมมา | แว่นขยายบนแถบบนสุด |
| ช่องพิมพ์ข้ออ้างอิง | พิมพ์ว่า มัทธิว 2:1-2 แล้วกระโดดไปที่ข้อนั้น ไม่ได้ค้นด้วยคำ | กลางหน้า ใต้แถบบน |

สองอันนี้ต่างกันมาก อันหลังคือทางลัดไปหาข้อ ไม่ใช่การค้นหาด้วยคำ

ใบ #7 ที่ค้างอยู่ก็เถียงกันเรื่องนี้ ฝั่งหนึ่งบอกว่ามีช่องค้นหาต้องทำให้เด่น หรือไม่ก็ไม่มีเลย ห้ามย่อเป็นไอคอน ซึ่งของที่เป็นอยู่ย่อเป็นไอคอนพอดี

**ผมไม่ตัดสินให้** สิ่งที่ต้องเคาะคือช่องไหนอยู่ ช่องไหนไป

## ยังไม่ได้พิสูจน์

1. **ผมตรวจหน้าแรกตอนที่ยังไม่ได้เลือกบท** ตัวบทพระคัมภีร์จริงยังไม่ได้ขึ้นบนหน้าตอนที่ผมวัด ความกว้างบรรทัดของตัวบทจึงยังไม่ได้วัด เกณฑ์ที่เรารับมาเองบอกว่าบรรทัดต้องไม่เกิน 80 ตัวอักษร กล่องเนื้อหาที่วัดได้ตอนนี้กว้าง 116 ตัวอักษร แต่ย่อหน้าจริงกว้าง 62 ตัวอักษร จึงยังสรุปไม่ได้จนกว่าจะเปิดบทจริง
2. **ยังไม่ได้ฟังด้วยโปรแกรมอ่านจอจริง** ที่ตรวจคือป้ายในโค้ด ไม่ใช่เสียงที่ออกมาจริง
3. **ยังไม่ได้วัดความเร็ว** ตัวเลข 0.1 กับ 1 กับ 10 วินาทีของกลาง ยังไม่ได้จับเวลา และตามกติกาต้องวัดบนเครื่องอ้างอิง ไม่ใช่บนโน้ตบุ๊ก
4. **ตรวจหน้าเดียว** เว็บรุ่น 2 มี 59 หน้า ที่เหลือยังไม่ได้แตะ
