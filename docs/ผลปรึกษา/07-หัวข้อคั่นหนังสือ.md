## 1. หัวข้อที่เสนอ

**เอาทั้งสองแท็บ** — พันธสัญญาเดิม 5 หมวด พันธสัญญาใหม่ 5 หมวด ทุกหมวดเรียงตามลำดับพระคัมภีร์ ไม่สลับที่ ไม่เรียงตามตัวอักษร

| 5 | **ภาพนิมิตถึงวาระสุดท้าย** | 1 เล่ม | วิวรณ์ |

ทุกหมวดเป็น **ช่วงที่ติดกัน** ในลำดับเดิมของไฟล์ ไม่ต้องย้ายเล่มไหนเลย — ตัดที่ตำแหน่ง OT `[5, 17, 22, 27, 39]` และ NT `[4, 5, 18, 26, 27]` ของอาเรย์ที่มีอยู่แล้วในโครงร่าง

**ข้อควรรู้ 3 ข้อ**

- ห้าหมวดคือจำนวนที่ถูกแล้ว **อย่ารวมสองหมวดผู้เผยพระวจนะเป็นหมวดเดียว 17 เล่ม** — รวมแล้วประหยัดที่ได้แค่ ~32 จุด (คิดให้ดูในข้อ 4) แต่เสียจุดสังเกตกลางรายการที่ยาวที่สุดของแท็บไป และ 17 เล่ม = 9 แถว = สูงกว่าหน้าจอที่มองเห็น กลายเป็นก้อนไร้ที่หมายเหมือนเดิม หมวดที่ใหญ่ที่สุดตอนนี้คือ 12 เล่ม = 6 แถว ≈ 296 จุด ซึ่ง **สั้นกว่าหนึ่งหน้าจอ** พอดี นั่นคือขนาดที่ควรเป็น
- **แท็บใหม่ต้องแบ่งด้วย** — ไม่ใช่เพราะ 27 เล่มยาว แต่เพราะช่วง โรม→ยูดา คือ 21 เล่มที่มีชื่อซ้ำกันเป็นคู่ ๆ (1–2 โครินธ์, 1–2 เธสะโลนิกา, 1–2 ทิโมธี, 1–2 เปโตร, 1–2–3 ยอห์น) ตาคนมองแล้วเบลอกว่าฝั่งพันธสัญญาเดิมอีก และคนไทยส่วนใหญ่เข้าเว็บนี้มาที่แท็บใหม่ก่อน ถ้าแท็บที่เปิดมาเจอเป็นแท็บเดียวที่ไม่มีหัวข้อ คนจะไม่รู้เลยว่าเว็บนี้มีหัวข้อให้
- **หมวดที่มีเล่มเดียว (กิจการ, วิวรณ์) ให้มีหัวข้อ** ถึงจะดูเปลือง 41 จุด — เพราะสองเล่มนี้คือเล่มที่คนไม่มีพื้นคริสเตียนเดาไม่ออกที่สุดว่าคืออะไร หัวข้อทำหน้าที่อธิบายให้ และช่องเดียวโดด ๆ ที่เหลือที่ว่างข้างขวา กลายเป็นจุดสังเกตทางสายตาที่ชัดมาก **อย่าทำให้ช่องเดียวนี้ยืดเต็มบรรทัด** เพราะจะไปเหมือนปุ่ม "อ่านทั้งบท" ซึ่งเป็นปุ่มคนละความหมาย

## 2. วิธีทำ

### 2.1 Markup — one `<ul>` per group, heading as a sibling *outside* it

หัวข้อ **ห้ามอยู่ใน `<ul>`** โดยเด็ดขาด: axe rule `list` บังคับว่า `<ul>`/`<ol>` มีลูกตรงได้แค่ `<li>`, `<script>`, `<template>` — ใส่ `<h3>` เข้าไปตรง ๆ = violation ทันที (โปรเจกต์นี้อยู่ที่ 0 violations)

เปลี่ยน `#bmGrid` จาก `<ul>` เป็น container `<div>` แล้วให้แต่ละหมวดเป็นบล็อกของตัวเอง:

```html
<div class="panel" id="bmPanel" role="tabpanel" tabindex="-1" aria-labelledby="tabNT">
  <div id="bmGrid">

    <div class="grp">
      <h3 class="grp-h" id="g-nt-1">
        ชีวิตของพระเยซู (พระกิตติคุณ) <span class="n">4&nbsp;เล่ม</span>
      </h3>
      <ul class="grid books" aria-labelledby="g-nt-1">
        <li><button type="button" aria-label="มัทธิว 28 บท">มัทธิว</button></li>
        <li><button type="button" aria-label="มาระโก 16 บท">มาระโก</button></li>
        <li><button type="button" aria-label="ลูกา 24 บท">ลูกา</button></li>
        <li><button type="button" aria-label="ยอห์น 21 บท">ยอห์น</button></li>
      </ul>
    </div>

    <div class="grp">
      <h3 class="grp-h" id="g-nt-2">จุดเริ่มต้นของคริสตจักร <span class="n">1&nbsp;เล่ม</span></h3>
      <ul class="grid books" aria-labelledby="g-nt-2">
        <li><button type="button" aria-label="กิจการ 28 บท">กิจการ</button></li>
      </ul>
    </div>
    <!-- …อีก 3 หมวด… -->

  </div>
</div>
```

**ข้อกำหนดแต่ละอย่าง และเหตุผล:**

| สิ่งที่ทำ | ทำไม |
|---|---|
| `<h3>` (ไม่ใช่ h2 ไม่ใช่ h4) | หัวเรื่องกล่องคือ `<h2 id="bmTitle">เลือกหนังสือ</h2>` อยู่แล้ว → ระดับถัดไปคือ h3 ไม่ข้ามระดับ ผ่าน axe `heading-order` |
| **หนึ่ง `<ul>` ต่อหนึ่งหมวด** ไม่ใช่ `<ul>` เดียว 39 ตัว | นี่คือประเด็นสำคัญที่สุดของข้อนี้ เครื่องอ่านหน้าจอจะพูดว่า "รายการ 5 รายการ" ต่อหมวด แทนที่จะเป็น "39 รายการ" ที่มี 5 รายการปลอมปน — จำนวนถูกต้องขึ้น ไม่ใช่แค่ไม่พัง MDN แนะนำตรง ๆ ว่า "when a group is used in the context of list, it is recommended to use multiple `<ol>`/`<ul>` with nested `<li>` children" |
| `aria-labelledby` ที่ `<ul>` ชี้ไป `<h3>` | `role="list"` รองรับ `aria-labelledby` → คนที่กระโดดเข้ากลางรายการด้วย virtual cursor ได้ยิน "รายการ ชีวิตของพระเยซู 4 รายการ" ไม่ต้องเลื่อนย้อนขึ้นไปหาหัวข้อ |
| ห่อด้วย `<div class="grp">` — **ไม่ใช่ `<section>`** | `<section>` ที่มีชื่อ = `role="region"` = landmark การมี 5 landmark ซ้อนอยู่ในไดอะล็อกคือ landmark noise ที่ไม่ช่วยอะไร `<h3>` ทำหน้าที่นำทางครบอยู่แล้ว |
| **ห้าม** ใส่ `role="group"` ที่ `<ul>` | role=group จะทับ role=list → จำนวนรายการหายทันที ตรงข้ามกับที่ต้องการ |
| **ห้าม** ใช้ `display:contents` บน `<ul>` เพื่อยัดทุกหมวดเข้ากริดเดียว | เคยเป็นบั๊กที่ลบ list semantics ทิ้งใน Chrome/Safari มาก่อน และ VoiceOver ยังไม่น่าไว้ใจ ไม่คุ้มเสี่ยง |
| ขั้นเลือกบท/เลือกข้อ **ไม่แตะเลย** | ยังเป็น `<ul class="grid nums">` เดี่ยว ๆ กับ `panel[role="group"]` เหมือนเดิม `resetGrid()` ต้องแก้ให้สร้าง `<ul>` ใหม่ใน `#bmGrid` แทนที่จะ reuse ตัวเดิม |
| เพิ่มบรรทัดเดียวใน `showBooks()` | `say(testament === 'OT' ? 'พันธสัญญาเดิม 39 เล่ม 5 หมวด' : 'พันธสัญญาใหม่ 27 เล่ม 5 หมวด')` — บอกโครงสร้างตอนสลับแท็บ ฟรี |

### 2.2 CSS — per-group sub-grid ชนะ `grid-column: 1 / -1`

**ใช้กริดย่อยต่อหมวด ไม่ใช่กริดเดียวแล้วให้หัวข้อ span** เหตุผลชี้ขาดคือ accessibility ไม่ใช่ visual: ถ้าใช้กริดเดียว หัวข้อต้องเป็น `<li>` (พัง item count) หรือใช้ `display:contents`/`subgrid` (พัง list semantics / support ไม่พอ) ส่วนภาพที่ได้เหมือนกันเป๊ะ เพราะทุก `<ul>` กว้างเท่ากันในคอนเทนเนอร์เดียวกัน คอลัมน์จึงตรงกันข้ามหมวดอยู่แล้ว

```css
/* ── ย้าย padding แนวนอนออกจาก .panel มาไว้ที่ลูก ───────────────────
   จำเป็นสำหรับ sticky: แถบหัวข้อต้องทึบเต็มความกว้าง โดยไม่ต้องใช้
   negative margin (ซึ่งจะดัน scrollable overflow ทางขวาในบางเบราว์เซอร์) */
.panel{ padding:.5rem 0 1rem; scroll-padding-top:3.5rem; }
.grid.books, .grid.nums, .grp-h{ padding-inline:.9rem; }

.grp{ margin-top:.55rem; }
.grp:first-child{ margin-top:0; }

.grp-h{
  position:sticky; top:0; z-index:1;
  display:flex; justify-content:space-between; align-items:baseline; gap:.5rem;
  margin:0;
  padding-block:.45rem .35rem;
  background:var(--paper);              /* ทึบ — ห้าม transparent */
  border-top:1px solid var(--line-soft);
  font-size:.85rem; font-weight:700; line-height:1.35; color:var(--ink-soft);
  text-wrap:pretty;
}
.grp:first-child .grp-h{ border-top:0; }
.grp-h .n{ font-weight:400; font-size:.8rem; white-space:nowrap; color:var(--ink-soft); }

/* จอคอมพิวเตอร์ 5 คอลัมน์ / จอเล็ก 2 คอลัมน์ — ของเดิมใช้ได้เลย
   เพราะทุก .grid.books ยังเป็น grid ของตัวเอง */
```

หมายเหตุ: `.panel{padding:.5rem 0 1rem}` ยังรักษาข้อกำหนดเดิมในโครงร่างไว้ (padding บน ≥ 5 จุด กันกรอบโฟกัสแถวแรกถูกตัดหัว)

### 2.3 Sticky — **ทำ** แต่เฉพาะขั้นเลือกหนังสือเท่านั้น

**คำตอบคือทำ** เหตุผลเป็นตัวเลข: พื้นที่ที่มองเห็นในแผงเลื่อนบนจอ 320×640 คือประมาณ 437 จุด แถบหัวข้อสูง ~32 จุด = **7.4% ของพื้นที่นั้น** ต่ำกว่าเพดาน 10% ที่ NN/g ใช้กับ persistent header บนมือถือ ราคาที่จ่ายคือ 0.65 แถว ส่วนที่ได้คือ **ผู้ใช้ไม่มีทางหลงว่าอยู่ตรงไหนได้เลย** ซึ่งคือปัญหาข้อเดียวที่หัวข้อมีไว้แก้ ถ้าไม่ sticky หัวข้อจะเลื่อนพ้นจอแล้วรายการก็กลับไปเป็นก้อนไร้ที่หมายเหมือนเดิมทันทีที่เลื่อนผ่าน

พฤติกรรมที่ต้องได้เป๊ะ ๆ:

1. `position:sticky; top:0` **สัมพันธ์กับ `.panel`** (ซึ่งเป็น `overflow:auto` → เป็น scrollport เอง) ไม่ใช่กับหน้าจอ — หัวข้อจึงไม่มีวันไปทับ `.modal-head` หรือแถบแท็บ
2. มีหัวข้อ **ค้างได้ทีละอันเท่านั้น** ไม่ซ้อนกัน — เป็นพฤติกรรมปกติของ sticky ที่ `top` เท่ากัน หัวข้อถัดไปจะดันอันเก่าขึ้นไป (push-off) ไม่ต้องเขียน JS
3. พื้นหลัง **ทึบ** (`--paper`) และเส้น `border-top` — ถ้าโปร่งใส ช่องหนังสือจะเลื่อนทะลุออกมาเห็น อ่านไม่ออกทันที
4. `scroll-padding-top:3.5rem` บน `.panel` — **นี่คือส่วนที่ห้ามลืม** WCAG 2.2 Understanding ของ SC 2.4.11 Focus Not Obscured (Minimum) ระบุ sticky header ไว้ตรง ๆ ว่าเป็นสาเหตุที่ทำให้ตกเกณฑ์ และระบุ `scroll-padding` เป็นวิธีผ่าน ถ้าไม่ใส่ ปุ่มที่กด Tab ไปถึงจะถูกแถบหัวข้อบัง
5. **ไม่ sticky ในขั้นเลือกบทและเลือกข้อ** — ขั้นนั้นไม่มีหัวข้อ ไม่ต้องทำอะไร
6. บนจอคอมพิวเตอร์ (5 คอลัมน์) ให้ sticky เหมือนกัน ไม่ต้องแยกโค้ด — ไม่มีข้อเสีย

- **"จดหมายฉบับอื่น ๆ" เลี่ยงข้อพิพาทเรื่องฮีบรูโดยตั้งใจ** การนับสมัยใหม่คือ เปาโล 13 + อื่น ๆ 8 (ฮีบรูอยู่ฝั่งอื่น ๆ) แต่ธรรมเนียมไทยเก่าและตำราบางเล่มนับ 14 + 7 (ฮีบรูอยู่กับเปาโล) เว็บสาธารณะไม่ควรไปตัดสินเรื่องผู้เขียนฮีบรูให้ใคร หัวข้อ "จดหมายฉบับอื่น ๆ" จึงจัดกลุ่มถูกตามฉบับมาตรฐานโดย **ไม่กล่าวอ้างเรื่องผู้เขียนเลย** — ปลอดภัยกับทั้งสองฝ่าย และคนทั่วไปก็เข้าใจทันที · [The Non-Pauline Epistles — Bible.org](https://bible.org/seriespage/5-non-pauline-epistles) · [Pauline epistles — Wikipedia](https://en.wikipedia.org/wiki/Pauline_epistles)

- **จุดยืนเรื่อง "ผู้พูดแทนพระเจ้า เล่มยาว/เล่มสั้น": รับเนื้อหา แต่ปฏิเสธการแทนที่** ข้อเสนอเดิมถูกในสาระ — ใหญ่/น้อย หมายถึงความยาวของหนังสือ ไม่ใช่ความสำคัญของผู้เผยพระวจนะ และมีคนอ่านผิดเป็นประจำ (วิกิพีเดียไทยของทั้งสองคำเขียนอธิบายข้อนี้ไว้เลย) แต่ถ้า **ตัดคำเดิมทิ้ง** จะเป็นการตัดผู้ใช้ออกจากคำที่เขาจะเจอในพระคัมภีร์เล่มจริง ในคำเทศนา และในผลค้นหาของกูเกิล นั่นคือความเสียหายจริง ทางที่ถูกคือทางที่คู่มือ plain language แนะนำสำหรับ *term of art*: **เก็บคำเดิมไว้ อธิบายมันตรงนั้น ไม่ใช่แทนที่มัน** — และคำกลอสนี้ไม่ได้ประดิษฐ์ขึ้นเอง โครงการคริสเตียนไทยที่ทำสื่อสำหรับคนนอกคริสตจักรใช้อยู่แล้ว (ชูใจ Project ตั้งชื่อตอนว่า "ผู้เผยพระวจนะ / ผู้พูดแทนพระเจ้า" ตรง ๆ) · [Where Technical Terms of Art Fit in Plain Language — WordRake](https://www.wordrake.com/resources/where-technical-terms-of-art-fit-in-plain-language) · [ผู้เผยพระวจนะใหญ่ — วิกิพีเดีย](https://th.wikipedia.org/wiki/ผู้เผยพระวจนะใหญ่) · [[EP.4] ผู้เผยพระวจนะ / ผู้พูดแทนพระเจ้า — ชูใจ Project](https://choojaiproject.org/prophets/) *(อ้างจากชื่อบทความในผลค้นหา — proxy บล็อกการเปิดหน้าจริง)*

- **ลำดับต้องเป็น "คำง่ายก่อน วงเล็บคำเดิมทีหลัง" — เหตุผลไม่ใช่ความสุภาพ แต่เป็นการกวาดสายตา** ถ้าเอาคำเดิมขึ้นก่อน หมวด 4 กับ 5 ของพันธสัญญาเดิมจะ **เริ่มด้วยตัวอักษรชุดเดียวกัน 13 ตัว** ("ผู้เผยพระวจนะ...") ต่างกันแค่ตัวสุดท้าย นั่นคือปัญหา "ก้อนไร้ที่หมาย" อันเดียวกับที่หัวข้อมีไว้แก้ ย้ายมาเป็น "เล่มยาว/เล่มสั้น" ในตำแหน่งที่กวาดตาถึงก่อน แล้วคำเดิมอยู่ห่างไปแค่ ~10 ตัวอักษร คนที่รู้จักคำเดิมอยู่แล้วก็ยังเห็นทันทีในบรรทัดเดียวกัน · [Understanding Headings and Labels (WCAG 2.4.6)](https://www.w3.org/WAI/WCAG22/Understanding/headings-and-labels)

- **ใส่วงเล็บเฉพาะคำที่ทึบ ไม่ใส่พร่ำเพรื่อ** — "ประวัติศาสตร์อิสราเอล" กับ "จดหมายของเปาโล" เป็นคำที่คนไทยทั่วไปเข้าใจอยู่แล้ว การเติมวงเล็บเข้าไปจะดูเหมือนแปลไทยเป็นไทย และเปลืองความกว้างที่มีแค่ ~291 จุด ส่วน "หมวดบัญญัติ / ปัญญานิพนธ์ / พระกิตติคุณ / ผู้เผยพระวจนะ" คือคำที่ต้องมีวงเล็บ **อย่าใช้ "เบญจบรรณ" ที่ไหนเลย** — เป็นคำบาลีสันสกฤตที่คนนอกคริสตจักรไม่มีทางเดาได้ และไม่ได้ช่วยการค้นหาเท่า "หมวดบัญญัติ" · [สมาคมพระคริสตธรรมไทย (thai.bible) — ใช้ "หมวดประวัติศาสตร์ / หมวดปัญญานิพนธ์ / หมวดผู้เผยพระวจนะใหญ่" เป็นชื่อหมวดมาตรฐาน](https://thai.bible/)

- **หัวข้อห้ามอยู่ใน `<ul>` และหนึ่ง `<ul>` ต่อหมวดคือคำตอบที่ถูกที่สุด** ไม่ใช่แค่เลี่ยง axe violation แต่ทำให้ **จำนวนรายการที่เครื่องอ่านหน้าจอประกาศแม่นขึ้นจริง** ("5 รายการ" ต่อหมวด แทน "39 รายการ") ซึ่งดีกว่าเดิม ไม่ใช่แค่ไม่พัง · [`<ul>` and `<ol>` must only directly contain `<li>`, `<script>` or `<template>` — Deque axe rules](https://dequeuniversity.com/rules/axe/4.7/list) · [ARIA: list role — MDN](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Roles/list_role)

- **sticky ต้องมาคู่กับ `scroll-padding-top` เสมอ** — WCAG 2.2 Understanding ของ SC 2.4.11 ระบุชื่อ "sticky headers" ไว้ตรง ๆ ในรายการสิ่งที่ทำให้ตกเกณฑ์ และระบุ scroll-padding เป็นวิธีผ่าน ถ้าใส่ sticky แล้วลืมบรรทัดนี้ โปรเจกต์จะหลุดจาก WCAG 2.2 AA ทันทีทั้งที่ axe อาจตรวจไม่เจอ (2.4.11 เป็นเกณฑ์ที่ต้องทดสอบด้วยคน) · [Understanding Focus Not Obscured (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum)

- **การใส่หัวข้อให้ส่วนย่อยเป็นสิ่งที่มาตรฐานเรียกร้องอยู่แล้ว** SC 2.4.10 Section Headings (AAA) เขียนว่าหัวข้อ "ให้ที่จับทางความคิด (mental handles) ที่ช่วยความเข้าใจ" และย้ำว่า **"visual presentation is not sufficient to identify document sections"** — คือแค่ทำช่องว่างคั่นไม่พอ ต้องเป็นหัวข้อจริง ๆ ตรงนี้เป็นการได้ AAA ฟรีหนึ่งข้อ · [Understanding Section Headings (WCAG 2.4.10)](https://www.w3.org/WAI/WCAG22/Understanding/section-headings)

**สรุปอย่างซื่อสัตย์:** คนที่ใช้บ่อยจนจำลำดับได้ ส่วนใหญ่ไปหนังสือที่อยู่ต้น ๆ แท็บ (ยอห์น สดุดี มัทธิว ปฐมกาล) — พวกนี้ **แทบไม่เสียอะไรเลย** คนที่เสียหนึ่งการปัดคือคนที่ไปเล่มท้าย ๆ ซึ่งเดิมก็ต้องปัดสองสามครั้งอยู่แล้ว การจ่าย 1 การปัดเพื่อให้คนที่ไม่รู้ว่าโอบาดีห์คืออะไรหาเจอได้ — คุ้ม

**ของอื่นที่ต้องยอมเสียด้วย**

- **ต้องรื้อ `resetGrid()` และ `showBooks()` ใหม่** เพราะ `#bmGrid` เปลี่ยนจาก `<ul>` เป็น `<div>` ขั้นเลือกบท/เลือกข้อต้องสร้าง `<ul>` ใหม่ข้างใน ไม่ใช่แค่เปลี่ยน className ของตัวเดิม เป็นงานแก้จริงประมาณ 20 บรรทัด
- **เสียงเครื่องอ่านหน้าจอยาวขึ้นเล็กน้อย** — ได้ยิน "หัวเรื่องระดับ 3" เพิ่มมา 5 ครั้งต่อแท็บ แลกกับการที่กด H กระโดดข้ามหมวดได้และรู้ตำแหน่งตัวเองตลอด คุ้มมาก
- **ถ้าผู้ใช้ขยายตัวอักษร 200%** หัวข้อจะกินที่มากขึ้นตามสัดส่วน (ทุกอย่างเป็น rem อยู่แล้ว) ที่ 200% แถบ sticky จะกิน ~15% ของแผง ยังอยู่ในเกณฑ์ แต่ควรทดสอบจริง

### สองข้อเสนอเพิ่ม (จำกัดแค่สอง ตามที่ขอ)

**ที่ถามมาเพิ่มอีกสองเรื่อง ตอบสั้น ๆ:**

## 5. ที่ต้องให้เจ้าของตัดสิน

**1. หัวข้อสองหมวดสุดท้ายของพันธสัญญาเดิม — เอาแบบไหน**
- (ก) `ผู้พูดแทนพระเจ้า เล่มยาว (ผู้เผยพระวจนะใหญ่)` — คำง่ายมาก่อน คนไม่มีพื้นเข้าใจทันที แต่ตกสองบรรทัดบนจอเล็ก **← ที่ผมแนะนำ**
- (ข) `ผู้เผยพระวจนะใหญ่ (เล่มยาว)` — สั้น บรรทัดเดียว แต่คนไม่มีพื้นต้องอ่านถึงวงเล็บก่อนจะเข้าใจ และหมวด 4 กับ 5 จะขึ้นต้นเหมือนกันจนแยกยาก

**2. หนังสือฮีบรู จะบอกว่าอยู่หมวดไหน**
- (ก) `จดหมายฉบับอื่น ๆ` 8 เล่ม (ฮีบรูอยู่กับยากอบ เปโตร ยอห์น ยูดา) — ตามฉบับมาตรฐานสมัยใหม่ ไม่พูดเรื่องคนเขียน **← ที่ผมแนะนำ**
- (ข) `จดหมายของเปาโล` 14 เล่ม (รวมฮีบรู) — ตามธรรมเนียมเก่าที่คริสเตียนไทยรุ่นก่อนคุ้น แต่เป็นการชี้ขาดเรื่องผู้เขียนที่นักวิชาการยังไม่ลงรอย

**3. หัวข้อจะค้างอยู่บนสุดตอนเลื่อนหรือไม่**
- (ก) ค้าง (sticky) — กิน 32 จุดจาก 437 จุดตลอดเวลา แต่ผู้ใช้รู้ตำแหน่งตัวเองเสมอ **← ที่ผมแนะนำ**
- (ข) ไม่ค้าง เลื่อนไปกับเนื้อหา — ได้ที่คืนมาเต็ม ๆ แต่พอเลื่อนพ้นหัวข้อไปแล้ว รายการก็กลับไปเป็นก้อนที่ไม่รู้ว่าตรงไหนอีก
