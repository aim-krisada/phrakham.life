## Q
เรากำลังออกแบบหน้าอ่านพระคัมภีร์ภาษาไทย (เว็บฟรี ผู้อ่านส่วนใหญ่เป็นคนไทยวัยกลางคนถึงสูงอายุ ใช้มือถือ) ขอความเห็นเชิงออกแบบ 3 ข้อ ตอบเป็นภาษาไทย สั้น ตรงประเด็น และอ้างเกณฑ์ WCAG 2.2 ให้ถูกต้องเป๊ะ (ถ้าไม่แน่ใจเลขข้อ ให้บอกว่าไม่แน่ใจ อย่าเดา)

บริบท
- หน้าอ่านเป็น "ม้วนเดียว" คือทั้งเล่มเลื่อนต่อเนื่อง ไม่มีกำแพงกั้นระหว่างบท
- ย่อหน้าเป็นของฉบับแปล ย่อหน้าหนึ่งยาวได้หลายข้อ เช่น มาระโก 4:1-8 เป็นย่อหน้าเดียว
- มี "ความรู้ประกอบ" 2 ระดับที่ต้องผูกกับตัวบท
  ระดับ ก. ระดับคำหรือสิ่งของในเรื่อง เช่น ภาพ "ดินตื้นบนชั้นหิน" ผูกกับข้อ 5 คำว่า "พื้นดินปนหิน"
  ระดับ ข. ระดับทั้งตอน เช่น บทความของผู้เขียนเว็บเรื่อง "อุปมาดินสี่แบบ" ผูกกับ มาระโก 4:1-20 ทั้งช่วง

แบบปัจจุบันของเรา (แบบ A)
มี "ราง" กว้าง 30px ทางซ้ายของตัวบท ใส่หมุดกลม 26px (พื้นที่กด 44px) หมุดวางตรงบรรทัดที่ข้อนั้นเริ่ม กดแล้วกล่องคำอธิบายกางออก "ใต้ย่อหน้าทั้งย่อหน้า"

แบบที่เจ้าของเว็บเสนอ (แบบ B) และเป็นแบบที่เว็บรุ่นเก่าของเราใช้อยู่จริง
ไม่มีรางและไม่มีหมุด ใช้ "ตัวคำในเนื้อ" เป็นปุ่มเอง เป็น button inline มี aria-expanded ขีดเส้นใต้ไว้ พอกดแล้วคำนั้นได้พื้นไฮไลต์ (#F7E9C9) และกล่องกางออก

คำถาม
1) แบบ A กับ แบบ B อันไหนดีกว่าสำหรับผู้อ่านกลุ่มนี้ และอันไหนแข็งแรงกว่าในแง่ WCAG 2.2 ระดับ AA เพราะอะไร ขอเหตุผลที่เป็นรูปธรรม เช่น ชื่อที่โปรแกรมอ่านจอจะอ่านออกมา ขนาดพื้นที่กด ความกำกวมว่าปุ่มนี้ของคำไหน

2) กล่องที่กางออกควรโผล่ตรงไหน
   ข้อ 2.1 โผล่ "ตรงจุดนั้นเลย" คือแทรกเป็นบล็อกกลางย่อหน้า ทำให้ย่อหน้าถูกผ่าเป็นสองท่อนชั่วคราวขณะเปิด
   ข้อ 2.2 โผล่ "ใต้ย่อหน้า" แบบที่เว็บรุ่นเก่าทำ
   อันไหนดีกว่า และมีผลเสียอะไรที่เรามองไม่เห็น โดยเฉพาะเรื่องตำแหน่งการเลื่อนหน้ากระโดด (layout shift) และเรื่องคนที่ใช้แป้นพิมพ์หรือโปรแกรมอ่านจอ

3) ถ้าเลิกใช้ราง แล้วความรู้ "ระดับทั้งตอน" (ข้อ ข.) ควรผูกกับอะไร เพราะมันไม่มีคำเดียวให้เกาะ
   ทางที่เราคิดไว้คือผูกกับหัวข้อย่อยของตอน เช่นคำว่า "อุปมาเรื่องดินสี่แบบ" แต่ผู้อ่านปิดหัวข้อย่อยได้
   มีทางที่ดีกว่านี้ไหม

ข้อห้ามของเรา ห้ามใช้ป็อปอัปทับตัวบท ห้ามใช้สัญลักษณ์ที่ต้องมีคำอธิบายกำกับ ปุ่มต้องมีพื้นที่กดอย่างน้อย 44x44 และเราถือเกณฑ์ contrast 7:1

## A
ขอเสนอความเห็นเชิงออกแบบ 3 ข้อ เพื่อให้เหมาะกับผู้สูงอายุบนมือถือและถูกต้องตามเกณฑ์ WCAG 2.2 ดังนี้ครับ

---

### 1. เลือกแบบ B (ใช้คำในเนื้อเป็นปุ่ม) ดีกว่าแบบ A ทั้งด้าน UX และ WCAG

* **เหตุผลด้าน UX (ผู้สูงอายุ):**
  * **แบบ A (มีราง):** เบียดพื้นที่แนวนอนของจอมือถือไปฟรีๆ 30-44px ทำให้ข้อความพระคัมภีร์เหลือพื้นที่แคบ บรรทัดจะตัดบ่อย อ่านยากขึ้นมากสำหรับผู้สูงอายุที่มักขยายฟอนต์เครื่องใหญ่
  * **แบบ B (คำในเนื้อ):** ไม่เสียพื้นที่หน้าจอ ผู้อ่านโฟกัสที่เนื้อหาได้เต็มที่

* **เหตุผลด้าน WCAG 2.2:**
  * **WCAG 2.2 SC 4.1.2 Name, Role, Value (ระดับ A):** แบบ B แข็งแรงกว่ามาก เพราะ Screen Reader จะอ่าน **Accessible Name** จากตัวคำได้ทันที เช่น *"พื้นดินปนหิน, ปุ่ม, พับอยู่"* ขณะที่แบบ A ถ้าวางหมุดไว้ที่ราง Screen Reader อาจอ่านแค่ *"ปุ่ม"* ซึ่งกำกวม (ต้องเขียน code ผูก `aria-labelledby` ซับซ้อนเพื่อไม่ให้ขัด **SC 2.4.4 Link Purpose (In Context)**)
  * **WCAG 2.2 SC 2.5.8 Target Size (Minimum) (ระดับ AA):** แบบ B ต้องระวังเรื่องพื้นที่กด ถ้าคำนั้นสั้นมาก (เช่น คำว่า "หิน") ตัวปุ่ม `inline-block` ต้องใส่ `padding` หรือขยาย `line-height` ของบรรทัดนั้นให้ได้พื้นที่กดรวมไม่ต่ำกว่า 24x24px (และปรับเป็น 44x44px ตามข้อกำหนดของคุณ)
  * **WCAG 2.1 SC 1.4.1 Use of Color (ระดับ A):** แบบ B ต้องขีดเส้นใต้คำนั้นเสมอ ห้ามใช้แค่สีเปลี่ยนอย่างเดียว และสีไฮไลต์ `#F7E9C9` กับตัวอักษรสีดำ ได้ค่า Contrast Ratio ประมาณ 13.5:1 (ผ่านเกณฑ์ 7:1 ของคุณแน่นอน)

---

### 2. ควรให้กล่องกางออก "ตรงจุดนั้นเลย" (ข้อ 2.1)

* **เหตุผลด้าน UX (ผู้สูงอายุ):**
  ย่อหน้าพระคัมภีร์ฉบับแปลบางย่อหน้ายาวมากบนจอมือถือ (อาจยาวถึง 2-3 ความสูงจอ) หากใช้ **ข้อ 2.2 (กางใต้ย่อหน้า)** เมื่อกดคำที่อยู่ต้นย่อหน้า กล่องจะไปเปิดอยู่ใต้ขอบล่างของจอ ผู้สูงอายุจะคิดว่า *"กดแล้วไม่เห็นมีอะไรเกิดขึ้น"*

* **เหตุผลด้าน WCAG 2.2:**
  * **WCAG 2.1 SC 2.4.3 Focus Order (ระดับ A):** การแทรกกล่องต่อจากบรรทัดที่กดทันที (ข้อ 2.1) ทำให้ลำดับการอ่านของ Screen Reader และการกด Tab แป้นพิมพ์ ไหลเข้าสู่เนื้อหาความรู้เพิ่มเติมได้ทันทีอย่างเป็นธรรมชาติ
  * **วิธีแก้ปัญหา Layout Shift (CLS):** 
    1. ใช้ CSS Animate การกางออกเพื่อลดความตกใจ
    2. เมื่อปิดกล่อง ให้ใช้ JavaScript คืนค่า Focus กลับมาที่ปุ่มคำเดิมเสมอ ตามหลัก Accessibility
    3. ห้ามใช้ `focusable` Element ไปดึงสายตาผู้ใช้จนหน้าจอกระโดดหลุดจากตำแหน่งที่กำลังอ่าน

---

### 3. การผูกความรู้ "ระดับทั้งตอน" (ข้อ ข.) โดยไม่ใช้ราง และไม่พึ่งหัวข้อย่อย

**ทางออกที่ดีกว่า:** ใช้ **"การ์ดแจ้งเตือนต้นตอน" (Inline Callout Card)** วางแทรกเป็นบล็อกเดี่ยวๆ ต่อจากเลขข้อแรกของตอนนั้น (เช่น ก่อนขึ้นข้อ 1)

* **รูปแบบ:** ทำเป็นบล็อกปุ่มกว้างเต็มหน้าจอ (Full-width) ตัวอย่างข้อความ: 
  `[ 📖 บทความประกอบ: อุปมาเรื่องดินสี่แบบ (มาระโก 4:1-20) ]`
* **ข้อดี:**
  1. **ไม่ขึ้นกับหัวข้อย่อย:** ถึงผู้ใช้จะปิดหัวข้อย่อย การ์ดความรู้นี้ก็ยังคงอยู่ เพราะถือเป็นเนื้อหาความรู้ ไม่ใช่หัวข้อโครงร่าง
  2. **ผ่านเกณฑ์ Target Size ง่ายมาก:** เป็นปุ่มบล็อกใหญ่ กดง่ายมากสำหรับนิ้วผู้สูงอายุ (ได้พื้นที่กดเกิน 44x44px แน่นอน)
  3. **WCAG SC 4.1.2:** Screen Reader อ่านเข้าใจชัดเจนทันทีว่าปุ่มนี้คือบทความของทั้งตอน ไม่ใช่แค่คำๆ เดียว
