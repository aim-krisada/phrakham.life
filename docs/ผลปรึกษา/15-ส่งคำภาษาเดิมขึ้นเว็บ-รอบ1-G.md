## A
ข้อแนะนำสำหรับการจัดข้อมูลและการออกแบบเว็บอ่านพระคัมภีร์ภาษาไทย บน Nuxt 4 (Static Generation) โดยยึดประสบการณ์ของผู้สูงอายุ สายตา เน็ตช้า และความถูกต้องของข้อมูลเป็นหลัก

1. การจัดเก็บข้อมูลภาษาเดิม 113MB
เปรียบเทียบ 3 แนวทาง

ทางเลือกที่ 4 ที่แนะนำ (Hydration Hybrid Pattern)

แนวทางที่แนะนำ: "ฝังข้อมูลกำกับขั้นต่ำไว้ใน HTML แล้วโหลด JSON ภาษาเดิมรายบทเฉพาะเมื่อเปิดใช้งาน"

HTML หลัก (ฉบับไทย): ให้ Node วาด HTML เฉพาะบทความภาษาไทย และใส่ Data Attribute เล็กๆ ไว้ที่คำหรือข้อไทย (เช่น data-word-id="..." หรือ data-strong="...")

JSON รายบท (1,190 ไฟล์): เก็บรายละเอียดทั้ง 5 ช่องของ MACULA แยกไว้ตามบท เช่น /api/macula/gen/1.json

การทำงานหน้าเว็บ:

ผู้ใช้เน็ตช้าอ่านเฉพาะภาษาไทย: ได้หน้า HTML เบาหวิว เปิดติดทันที

เมื่อผู้ใช้กดปุ่ม "เปิดคอลัมน์ภาษาเดิม" ระบบค่อยไป fetch JSON ของบทนั้นๆ มาแมปกับ Data Attribute ในหน้าเว็บ เพื่อแสดงผลคู่กัน

หมายเหตุเรื่อง Google: เนื่องจากโจทย์ระบุชัดว่าคนจำได้แค่ถ้อยคำไทยต้องพึ่ง Google Search การทำให้ Google เก็บคำไทยได้สมบูรณ์บน HTML จึงเพียงพอต่อโจทย์แล้ว การนำภาษาเดิมไปใส่ใน HTML จะทำให้ขนาดไฟล์ใหญ่ขึ้น 3–5 เท่าโดยไม่เพิ่มประโยชน์ด้าน Search สำหรับผู้ใช้วัยกลางคนถึงสูงอายุที่ค้นด้วยภาษาไทยเป็นหลัก

2. การจัดการช่อง "คำแปลสั้นภาษาอังกฤษ" (Gloss)

ผู้อ่านสูงอายุไทยจำนวนมากไม่ได้เชี่ยวชาญภาษาอังกฤษ และอาจเกิดความสับสนว่าเป็นคำแปลฉบับใหม่ หรือแปลผิดจากภาษาไทย

ข้อเสนอแนะในการแสดงผล

แยกมิติการมองเห็น (Visual Separation): ห้ามนำคำแปลอังกฤษมาวางขนานในระดับเดียวกับเนื้อหาภาษาไทยเด็ดขาด

แสดงเมื่อมีการกด/แตะเท่านั้น (On-Demand Modal/Popover):

ในแถบภาษาเดิม ให้แสดงเฉพาะ "ตัวคำภาษาเดิม (ฮีบรู/กรีก)" + "รหัสพจนานุกรม/รูปผัน"

เมื่อผู้ใช้แตะที่คำภาษาเดิม ให้เปิด Popover หรือ Card รายละเอียดขึ้นมา

ติดป้ายกำกับภาษาอังกฤษให้ชัดเจนด้วยภาษาไทย:

ใน Popover รายละเอียดคำ ให้ใส่หัวข้อกำกับชัดเจน เช่น:

คำแปลอังกฤษสั้น (Gloss): In the beginning

พจนานุกรม: H7225

ไม่แน่ใจเกณฑ์เรื่องระดับความรู้ภาษาอังกฤษของผู้สูงอายุกลุ่มเป้าหมาย จึงแนะนำให้ทำ "ปุ่มปิดการแสดงคำแปลอังกฤษ" ไว้ในหน้าตั้งค่าการอ่านด้วย เพื่อให้ผู้ใช้ซ่อนได้หากรู้สึกเกะกะตา

3. การรับมือข้อที่เหลื่อมกัน (3 ข้อชน และ 71 ข้อไม่มีไทย)

หลักการยึดผู้อ่านเป็นศูนย์กลาง: ผู้ใช้กลุ่มสูงอายุอ่านเพื่อความเข้าใจและความต่อเนื่องของบริบท การเห็นข้อความขาดหายไป หรือเห็นตัวบทภาษาเดิมลอยๆ โดยไม่มีภาษาไทยคู่ จะสร้างความสับสนอย่างมากว่าเว็บเสีย หรือมีข้อความตกหล่น

กรณี ก: 3 ข้อที่แปลแล้วไทยชี้ไปข้อต้นฉบับเดียวกัน (อิสยาห์ 63:19, เนหะมีย์ 7:67, สดุดี 13:6)

สิ่งที่ควรแสดง: ไม่ต้องซ่อน ให้แสดงคอลัมน์ไทยตามปกติ แต่ในฝั่งภาษาเดิม ให้ทำการ "รวมเนื้อหาภาษาเดิม (Merge Group)" ของข้อต้นฉบับที่เกี่ยวข้องมาแสดงจับคู่กับข้อไทยนั้น

เหตุผลผู้ใช้: ผู้อ่านฉบับไทยจะยังอ่านได้ต่อเนื่องไม่สะดุด และเมื่อเปิดดูภาษาเดิม จะเห็นบริบทของต้นฉบับครบถ้วนโดยไม่มีเนื้อหาฮีบรู/กรีกส่วนใดหายไป

กรณี ข: 71 ข้อที่ต้นฉบับมี แต่ฉบับไทยไม่มี (เช่น คำโปรยหัวสดุดี)

สิ่งที่ควรแสดง: แสดงข้อภาษาเดิมนั้นขึ้นมา พร้อมใส่กล่องข้อความฝั่งไทยว่า [ฉบับแปลไทยรวมเนื้อหานี้ไว้ในข้อก่อนหน้า/ไม่มีในฉบับนี้] หรือแสดงคำแปลภาษาเดิมสั้นๆ (ถ้ามี) โดยใช้สีตัวอักษรที่ต่างออกไป (เช่น สีเทาอ่อน)

เหตุผลผู้ใช้:

การ ซ่อนไปเลย จะทำให้ผู้ใช้ที่ตั้งใจมาศึกษาภาษาเดิมหาข้อนั้นไม่เจอ และเข้าใจผิดว่าข้อมูลในเว็บไม่ครบถ้วน

การ แสดงภาษาเดิมไว้ แล้วใส่หมายเหตุฝั่งไทย ช่วยให้ผู้ใช้อ่านภาษาเดิมได้ครบตามโครงสร้างจริง และเข้าใจทันทีว่าทำไมฝั่งไทยถึงไม่มีข้อความ โดยไม่รู้สึกว่าระบบขัดข้อง

2.2 Structural Constraint Check:

ตรวจสอบว่าข้อที่เกิดการชนกัน ต้องเป็นไปตาม Index ที่กำหนดไว้เป๊ะๆ เท่านั้น (อิสยาห์ 63:19, เนหะมีย์ 7:67, สดุดี 13:6) หากมีข้ออื่นชนกันเพิ่มขึ้นมา ให้ Fail ทันที

ตรวจสอบว่าข้อที่มีเฉพาะภาษาเดิม ต้องมีจำนวนเท่ากับ 71 ข้อ พอดี

ด่านที่ 3: ตรวจสอบความสมบูรณ์ของข้อมูลรายคำ (Data Field Validation)

3.1 Schema Validation: วนลูปตรวจทุกคำใน 613,652 คำ ว่ามี Key ครบทั้ง 5 ช่อง (คำที่ปรากฏ, รูปพจนานุกรม, รหัสคำ, รหัสรูปผัน, คำแปลอังกฤษ) และไม่มีค่าเป็น null หรือ undefined

3.2 Word Index Continuity Check: ตรวจสอบว่าลำดับคำ (Word Index) ภายในแต่ละข้อเรียงต่อกันอย่างถูกต้อง ไม่มีการข้ามเลข หรือลำดับสลับกัน

ด่านที่ 4: ตรวจสอบไฟล์ผลลัพธ์หลังการสร้าง (Post-Generation Audit)

4.1 HTML & JSON File Existence: ตรวจสอบว่าใน Output Folder มีไฟล์ HTML ครบ 1,190 ไฟล์ และมีไฟล์ JSON ภาษาเดิมครบ 1,190 ไฟล์ (หรือ 66 ไฟล์ ตามโครงสร้างที่เลือก)

4.2 DOM Extraction Audit (สุ่มหรือตรวจทั้งหมด): ให้สคริปต์เปิดอ่านไฟล์ HTML และ JSON ที่สร้างเสร็จแล้ว นับจำนวนข้อภาษาไทยเทียบกับจำนวนข้อภาษาเดิมที่แมปได้ ยืนยันว่า ไม่มีข้อไทยใดเลยที่กลายเป็นค่าว่าง (Empty Paragraph)
