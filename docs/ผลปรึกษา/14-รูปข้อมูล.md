# รอบ 14 — ข้อมูลตัวบทควรเป็นรูปไหน

> **พี่เอมสั่ง 6 ก.ย. 2569** *"ไม่รู้อันไหนดีกว่า ปรึกษา g"*

## โจทย์ — สองบ้านทำคนละแบบ และอยู่ด้วยกันไม่ได้

| | **แบบ ก** (ที่อัมกิตทำอยู่) | **แบบ ข** (ที่ GitHub ทำอยู่) |
| --- | --- | --- |
| เก็บในกิตยังไง | ไฟล์บีบก้อนเดียว **7.0 MB** ด้วย Git LFS | **ไฟล์ JSON แยกบท 1,189 ไฟล์** รวม 34 MB |
| ถึงผู้อ่านยังไง | โค้ดฝั่งเซิร์ฟเวอร์อ่านซองตอนสร้าง ⇒ **ฝังตัวบทลง HTML** | ผู้อ่านโหลดไฟล์ JSON ตอนเปิดหน้า |

## ⭐ ข้อสรุป — **แต่ละแบบชนะคนละเรื่อง ⇒ เอาที่ชนะของทั้งคู่**

**คำถามนี้จริง ๆ เป็น 2 คำถามที่ไม่เกี่ยวกัน และเราเผลอมัดรวมเป็นคำถามเดียว**

| คำถาม | คำตอบ | ของใครชนะ |
| --- | --- | --- |
| **เก็บในกิตยังไง** | **ไฟล์ JSON แยกบท ⛔ ไม่บีบ ⛔ ไม่ใช้ LFS** | **GitHub** |
| **ส่งถึงผู้อ่านยังไง** | **ฝังตัวบทไทยลง HTML ตอนสร้างเว็บ** | **อัมกิต** |

### ทำไมเก็บเป็นไฟล์แยกบท

1. ⭐ **ไฟล์บีบก้อนเดียวใน LFS มองไม่เห็นว่าใครแก้คำไหน** ⇒ กิตเห็นเป็นก้อนไบนารีเปลี่ยนทั้งก้อน
   ⇒ แยกไฟล์แล้ว **แก้คำผิดในสดุดี 23 จะเห็นชัดในคำขอรวมว่าเปลี่ยนคำไหนเป็นคำไหน**
2. **สองคนแก้คนละเล่มพร้อมกัน** ⇒ ก้อนเดียวชนกันทันที ⇒ แยกไฟล์รวมได้สบาย
3. **34 MB เป็นข้อความล้วน ⇒ กิตธรรมดารับไหวสบาย** ⇒ ⛔ ไม่ต้องเพิ่มความยุ่งของ LFS

### ทำไมต้องฝังตัวบทลง HTML

⭐ **นี่คือเรื่องเป็นเรื่องตายของเว็บนี้** เพราะเราตัดช่องค้นหาออกแล้ว **คนที่จำได้แค่ถ้อยคำต้องพึ่งกูเกิล**

- **ฝังลง HTML** ⇒ กูเกิลได้ตัวบทตั้งแต่การตอบครั้งแรก ⇒ **เก็บครบแน่นอน**
- **โหลดด้วยโค้ดทีหลัง** ⇒ กูเกิลต้องกลับมารันโค้ดอีกรอบในคิวที่สอง ⇒ **มีโอกาสหลุดสูง โดยเฉพาะไฟล์ใหญ่อย่างสดุดี 119 ที่ 131 KB**

⇒ ⭐ **และเรามีหลักฐานของตัวเองอยู่แล้ว** ⇒ รุ่น 2 วาดตัวบทด้วยโค้ด ⇒ **บัญชีหน้ามี 84 หน้า และมีบทพระคัมภีร์ศูนย์หน้า**

**อีก 2 เรื่องที่ได้ฟรีจากการฝัง**
- **คนที่ปิดจาวาสคริปต์** ⇒ ฝังแล้วอ่านได้ 100% · โหลดทีหลังแล้ว **หน้าว่างเปล่า**
- **คนเน็ตช้า** ⇒ ฝังแล้วเห็นตัวหนังสือทันทีที่ HTML มาถึง ⛔ ไม่ต้องรอโค้ดโหลด

## ⭐ ท่าที่จะใช้จริง

**ชั้นข้อมูลของเราแยกไว้ 3 ชั้นอยู่แล้ว ⇒ ใช้ความต่างนั้นเลย**

| ชั้น | ใครใช้ | ส่งยังไง |
| --- | --- | --- |
| `read/` ตัวบทไทย · รอยย่อหน้า · เลขข้อ · เชิงอรรถ | **ทุกคนที่เปิดหน้า** | ⭐ **ฝังลง HTML ตอนสร้าง** |
| `word/` ชั้นวิเคราะห์คำภาษาเดิม | คนที่กดดูคำ | โหลดตอนกด |
| `sense/` พจนานุกรม | คนที่กดดูความหมาย | โหลดตอนกด |

⇒ **หน้าหนึ่งจึงเบา** เพราะฝังเฉพาะตัวบทไทย ⛔ ไม่ฝังภาษาเดิมที่หนักกว่ามาก

## ราคาที่ต้องจ่าย และเช็กแล้วว่ารับได้

| เรื่อง | ตัวเลข | รับได้ไหม |
| --- | --- | --- |
| ขนาดเว็บที่สร้างออกมา | ราว **35-50 MB** (1,189 หน้า) | ✅ เพดานของ GitHub Pages คือ 1 GB ⇒ ใช้ไม่ถึง 5% |
| แบนด์วิดท์ | เพดาน 100 GB ต่อเดือน | ✅ |
| ที่เก็บโตขึ้นทุกครั้งที่สร้างไหม | ⛔ ไม่ ⇒ **ถ้าไม่คอมมิตไฟล์ที่สร้างเสร็จลงประวัติ** | ⚠️ **ต้องระวังข้อนี้** |

⚠️ **ที่ปรึกษาบอกเองว่าไม่แน่ใจว่าเพดานพวกนี้บังคับเด็ดขาดแค่ไหนในทางปฏิบัติ** ⇒ เป็นตัวเลขจากเอกสารทางการ

## ⚠️ 3 อย่างที่ต้องทำกันไว้ เพราะบทสั้นมีเยอะ

บทอย่าง **สดุดี 117 มีสองข้อ** ⇒ กูเกิลอาจมองว่าเป็นหน้าเนื้อบาง

1. **ใส่ที่อยู่หลักกำกับทุกหน้า** (`rel="canonical"`)
2. **ใส่ข้อมูลโครงสร้างบอกว่าหน้านี้คือบทไหนของเล่มไหน**
3. **มีปุ่มบทก่อนหน้ากับบทถัดไป และลิงก์กลับไปหน้าเล่ม** ⇒ ให้กูเกิลเห็นว่าบทสั้นเป็นส่วนหนึ่งของคลังใหญ่

## ที่ยังไม่ได้ทำ

1. **ปรึกษาได้ 2 รอบ และมาจากฝั่ง G ฝั่งเดียว** ⇒ กติกาบ้านเราคืออย่างน้อย 3 รอบ ⇒ **ยังไม่ครบ**
2. **ยังไม่ได้ถาม N** ⇒ ควรถาม เพราะรอบ 13 N เห็นต่างจาก G แล้วได้ของดี
3. **ยังไม่ได้วัดของจริง** ⇒ ตัวเลข 35-50 MB เป็นการประมาณของที่ปรึกษา ⛔ ยังไม่ได้สร้างจริงแล้วชั่ง
